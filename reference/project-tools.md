# Инструменты разработки и анализа проектов

Проверено: 2026-11-08. Это каталог внешних проектов и правила выбора, а не установленные сервисы.
Карпати / Karpathy / «Карпат» / Consilium / «консилиум» относятся здесь к одному проекту LLM Council; отдельного третьего форка нет.

## Выбор под задачу

| Задача | Что учитывать | Результат |
|---|---|---|
| Создание или сопровождение программного проекта, передача между AI-разработчиками | AGENTS.md | Краткие проверенные инструкции в самом рабочем репозитории |
| Простая правка, перевод, ясное поручение | Подходящий локальный материал | Выполненная задача без лишней оркестрации |
| Выбор продукта, архитектуры, несколько убедительных вариантов | LLM Council | Альтернативы, критика, разногласия, итог с основаниями |
| Разработка приложения с несколькими агентами, обменом сообщениями и инструментами | AutoGen как справочник; сравнить с поддерживаемыми альтернативами | Обоснованный выбор архитектуры и среды исполнения |
| Автоматизация в текущем стеке Telegram / Sheets / n8n | Сначала skills/n8n/ | Простой рабочий процесс; агенты только при доказанной пользе |

Все три источника оцениваются при подборе для новой задачи, даже если локальный скилл уже найден. AGENTS.md применяется как формат инструкций; Council и AutoGen не нужно запускать для каждого проекта. В NS использовать только для соответствующей технической или аналитической задачи, не переносить экономику цифровых продуктов на уборку.

## AGENTS.md — инструкции для AI-разработчиков

- Наш форк: https://github.com/Demik-777/agents.md
- Сайт формата: https://agents.md
- Проверенный commit: `d001185d792eb6402a58e4cbef1c228b309ec25d`.
- [README проверенной версии](https://github.com/Demik-777/agents.md/blob/d001185d792eb6402a58e4cbef1c228b309ec25d/README.md).
- Тип: открытый формат Markdown-инструкций и сайт с примерами. Это не Codex CLI/CMD, не агентный runtime и не дополнительная модель.
- Когда полезен: разработка и сопровождение приложений, передача проекта между людьми и AI-ассистентами, воспроизводимый запуск и проверки.
- Порядок: прочитать существующий AGENTS.md рабочего проекта; при необходимости создать или обновить его в рамках поручения на разработку. Корневой файл содержит общие правила, вложенные — специфику отдельных частей. Детали обнаружения и приоритета проверять по документации используемого инструмента.
- Содержимое: назначение проекта, структура кода, проверенные команды установки/запуска/тестирования, стиль, ограничения и критерии готовности. Команды брать из реального кода и конфигурации; неизвестное явно отмечать. Хранить файл рядом с кодом, поддерживать при изменениях проекта.
- В каждом проекте указывать его направление: NS Reinigungsdienst либо Maoris Digital Lab; не смешивать данные и бизнес-правила.
- Не копировать шаблонные pnpm-команды или правила тестирования без проверки стека. Короткий AGENTS.md с проверяемыми правилами предпочтительнее полного каталога инструкций.
- Codex поддерживает AGENTS.md; для Claude и других ассистентов проверять поддержку либо явно подключать файл через инструкции среды. Само наличие форка не обеспечивает чтение файла всеми моделями.
- Официальная справка Codex: https://developers.openai.com/codex/guides/agents-md
- Статус: форк и README проверены 2026-11-08. Добавление в каталог не означает установку программы или изменение всех существующих проектов.

## LLM Council — консилиум Карпати

- Наш форк: https://github.com/Demik-777/llm-council
- Источник: https://github.com/karpathy/llm-council
- Проверенный commit: `92e1fccb1bdcf1bab7221aa9ed90f9dc72529131`.
- [README проверенной версии](https://github.com/Demik-777/llm-council/blob/92e1fccb1bdcf1bab7221aa9ed90f9dc72529131/README.md).
- Тип: приложение + методика сравнения ответов нескольких LLM.
- Когда полезен: спорные решения, сравнение архитектур, критика продуктовой гипотезы, оценка нескольких подходов.
- Методика: независимые ответы → анонимизированная взаимная оценка → итог председателя.
- Выход: рекомендация, доводы, сохранившиеся разногласия, непроверенные предположения и следующий шаг. Большинство голосов не подтверждает факт; фактические утверждения проверяются источниками.
- В обычном чате можно применить многосторонний разбор одной моделью. Называть его именно так; не выдавать за независимые ответы разных провайдеров.
- Реальный запуск: Python/FastAPI, uv, Node/npm и React/Vite; OpenRouter API, настроенные модели и API-бюджет. Для вызова из чата дополнительно нужен доступный инструмент/API к работающему сервису.
- Статус интеграции: исходники доступны; работающий сервис и подключение к чатам в рамках этой настройки не проверялись.
- Автор README описывает проект как эксперимент без обязательств поддержки. Перед развёртыванием проверить зависимости, конфигурацию, обработку ошибок и актуальность моделей.

## AutoGen — архитектура нескольких агентов

- Наш форк: https://github.com/Demik-777/autogen
- Источник: https://github.com/microsoft/autogen
- Проверенный commit: `d07c667a3239ea4ab7af62a53b0f4ff205a1f23d`.
- [README проверенной версии](https://github.com/Demik-777/autogen/blob/d07c667a3239ea4ab7af62a53b0f4ff205a1f23d/README.md).
- Тип: программный фреймворк; примеры AgentChat, обмена сообщениями, инструментов и исполнения агентных задач.
- Когда полезен: проектирование и разбор систем с несколькими агентами, анализ существующего AutoGen-кода, прототипы для сравнения подходов.
- Перед выбором: показать преимущество перед одним агентом или n8n; определить роли, контракты данных, завершение, лимит итераций, стоимость, тайм-ауты и восстановление после ошибок.
- Состояние: README проверенного форка сообщает об архивировании исходного проекта и рекомендует Microsoft Agent Framework. Архивность upstream и состояние нашего форка — разные вещи; перед внедрением проверить оба.
- Для нового production-проекта не выбирать AutoGen автоматически. Сравнить с текущим стеком и поддерживаемыми альтернативами; Microsoft Agent Framework — кандидат для отдельной актуальной проверки, не уже выбранная замена.
- Реальный запуск: совместимая среда Python или .NET, зависимости, модельный клиент/API и требуемые инструменты. Наличие описаний агентов не запускает их.
- Статус интеграции: исходники доступны; установка, работающий runtime и подключение к чатам в рамках этой настройки не проверялись.

## Порядок применения и обновления

1. Определить направление и результат задачи.
2. Прочитать этот краткий каталог и названия/описания подходящих локальных материалов.
3. Выбрать обычно 1–3 источника, загрузить нужные инструкции и зависимости.
4. Если нужен код внешнего проекта, получить актуальную ветку и commit его форка; читать выбранные файлы на одном commit. Полный AutoGen в контекст не загружать.
5. Указать, что применено: методика, пример кода либо реально запущенный инструмент. Не заявлять запуск без результата.
6. Установка, развёртывание, платные API-вызовы и изменения форков выполняются только в пределах поручения. Каталог сам их не разрешает.
7. При смене версии обновить проверенную дату, commit и состояние источника. Не синхронизировать форки и не переписывать их историю автоматически.
