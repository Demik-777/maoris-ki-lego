# KI-Lego — быстрый подбор и выполнение

1. Определить результат, проверяемый критерий готовности, ограничения и контекст: NS, MDL или иной/общий проект. Продолжение задачи выполнять с текущей сборкой; короткий перевод/уточнение — напрямую.
2. Начать с уже видимых названий/описаний установленных скиллов и краткого локального поиска. При доступном Python выполнить `python3 scripts/route.py search --query '<краткая задача>' --scope NS|MDL|general` из каталога скилла. Он читает индекс и частный журнал локально, возвращает до трёх кандидатов и трёх относящихся к запросу выводов. Не выводить весь catalog.json в контекст. Результат поиска — кандидаты, не доказательство доступа или применения.
3. Прочитать полную инструкцию только выбранных скиллов и обязательные зависимости. Обычно достаточно одного основного средства; 1–3 — ориентир, не квота. Незнакомые задачи поддерживать через поиск нужных возможностей. Если уверенного совпадения нет — один адресный поиск по недостающей возможности; углубляться только из-за конкретного пробела. Не устанавливать лишнее.
4. Использовать локальный снимок каталога без обязательного сетевого обхода при каждом старте. Для свежих данных, новых зависимостей, явной проверки или устаревшего/неполного индекса читать [discovery.md](references/discovery.md). При недоступном Python — использовать уже видимые метаданные и короткий [указатель](references/quick-index.md).
5. Начать одной короткой фразой о результате и подходе; подробности сборки давать при существенном выборе или по запросу. Выполнить поручение и проверить результат по критерию готовности. Подбор не заменяет создание. Сервисы проверять по фактическому доступу; советы из памяти не считать действующими подключениями. Разделять NS и MDL; соблюдать правила среды и рабочего проекта. Не выдавать методику за реальный запуск.
6. При внешнем действии с неопределённым результатом сначала проверить фактическое состояние; вслепую не повторять. Для восстановления и спорного завершения читать [interaction.md](references/interaction.md). Читать [operations.md](references/operations.md) при конфликте инструкций, многошаговой передаче или изменении скилла. [assembly.md](references/assembly.md) — открытые примеры, читать только при необходимости.
7. При существенном сбое, пользовательской поправке или подтверждённом удачном приёме применять [learning.md](references/learning.md): сохранить краткий вывод в частном журнале, проверить его перед будущим применением. Обычные успешные ответы и короткие переводы не логировать. Значимые решения проекта сохранять с проектом.

Скилл действует там, где доступен ассистенту. Каталог — указатель, журнал — сохранённые наблюдения; они не дают доступа ко всем чатам. Целостность выпуска проверять при обновлении/диагностике через scripts/verify_release.py, а не при каждом запросе. Свежесть и доступ не выдумывать.
