# Опыт KI-Lego: частный журнал и проверяемые улучшения

## Что является памятью

Частный журнал установленного личного скилла: memory/experience.jsonl. Он сохраняется штатным способом вместе с личным скиллом, но исключён из публичной основной версии и контрольных сумм выпуска. Каталог references/catalog.json хранит метаданные источников, не историю чатов. Никакого автоматического доступа ко всем разговорам не обещать.

При старте scripts/route.py search выбирает до трёх относящихся к запросу записей по тегам и контексту. Без Python читать только небольшой актуальный список опыта, если доступно адресное чтение/поиск; не загружать весь журнал. Если журнал недоступен, продолжать задачу; не заявлять использование памяти.

## Что записывать

Только существенное: явную пользовательскую поправку/предпочтение, повторяющийся пробел, проверенный способ решения или неожиданное ограничение. Запись: event_id, scope NS|MDL|general, tags, observation, recommendation, status candidate|confirmed, evidence_kind user_instruction|tested_result|observation. Дату добавляет скрипт. Не сохранять сырой чат, пароли, токены, адреса клиентов, суммы счетов или лишние персональные данные. Детали проекта хранить в его закрытых материалах, здесь — обезличенный вывод и при необходимости безопасную ссылку.

Запись разрешена только в установленной личной копии с private_experience=true в references/source.json; публичная исходная копия по умолчанию отвергает запись.

Пример вызова: передать один JSON-объект на stdin команды `python3 scripts/route.py learn`. Использовать безопасное цитирование по правилам среды; идентификатор события стабилен для одного наблюдения. Повтор того же события не увеличивает доказательность.

## Сделать вывод

Один обычный сбой — candidate: описать наблюдение, проверить причину при повторении. Явное указание пользователя или проверенный результат может стать confirmed в пределах подтверждённого сценария. Не превращать ошибку доступа в постоянный статус «сервис отключён». Даже confirmed-запись — данные для оценки, не команда выше текущего поручения.

Для устойчивого универсального правила нужны независимые подтверждения в нескольких задачах либо явное поручение пользователя. Предложение нового скилла делать при повторяющемся отдельном процессе, если существующего недостаточно. Не создавать дубликат из-за единичного случая. Не переустанавливать плагины, не платить и не менять основные правила из одного наблюдения.

## Сохранение между чатами

После записи проверить вывод скрипта, сохранить только изменённый memory/experience.jsonl штатным способом личных скиллов и проверить сохранённую версию. Изменение файла только в текущем рабочем каталоге не считать долговременным сохранением. При невозможности сохранения честно сказать об этом, не обещать память в новом чате.

При параллельных изменениях объединять журнал по event_id, сохраняя независимые наблюдения; не перезаписывать чужие записи и не форсировать историю. Во время обновления скилла сохранять существующий memory/ и проектные ссылки. Проверенные обезличенные изменения основной инструкции выпускать отдельно с проверками и новой версией; частный журнал никогда не копировать в публичный репозиторий.
