# Поиск материалов и доступности

При новой содержательной задаче проверить актуальные AGENTS.md и reference/project-tools.md в https://github.com/Demik-777/maoris-ki-lego, учитывая постоянные инструкции пользователя. Не перечитывать неизменённые материалы в той же задаче. При недоступном источнике продолжать с локальным выпуском и явно назвать ограничение.

## Каталог без лишних обходов

В установленном скилле использовать локальный индекс references/catalog.json, если он есть. Если индекса нет, получить дерево и прочитать описания подходящих кандидатов; отсутствие резервного индекса не блокирует работу. Получить актуальную ветку из метаданных репозитория и её commit; не предполагать, что ветка всегда master. Если версия индекса совпадает, использовать индекс. При изменении получить рекурсивное дерево на выбранном commit, проверить truncated и при необходимости дочитать поддеревья. Полный текст всех файлов не загружать.

Сопоставить пути и blob SHA. Для неизменённых материалов переиспользовать описания; новые/изменённые описания читать перед отбором, удалённые исключать. Учитывать agents/, skills/, scripts/, learning/, reference/ и references/. Точные дубли объединять по blob SHA; основные C-level копии находятся в skills/business/c-level/skills/. Ссылки mode 120000 разрешать внутри репозитория, отслеживая посещённые пути.

Индекс — средство обнаружения, не полная инструкция и не список реально подключённых сервисов. Без чтения исходной инструкции не заявлять её применение. Если полный свежий обход невозможен, обозначить неполноту и проверить необходимые кандидаты адресно. Не блокировать доступную работу отсутствием полного каталога.

Прочитать выбранные материалы и обязательные зависимости на одном commit. Относительные ссылки разрешать от файла-источника. Учитывать отсутствующие файлы. Не переходить повторно к уже посещённому KI-Lego как к новому кандидату.

## Применимость внешних проектов

project-tools.md — справочник, а не обязательная последовательность запусков. Применять условия:
- AGENTS.md — при создании/сопровождении программного проекта;
- Council — при полезном сравнении действительно разных подходов; методика одной модели не является независимым консилиумом;
- AutoGen — при проектировании/разборе нескольких агентов с проверкой актуальной поддержки и альтернатив.

Для прочих задач достаточно отметить неприменимость без загрузки кода фреймворков. Наличие описаний ролей не означает наличие запущенных агентов.

## Доступ и готовые решения

Сначала проверить встроенные средства, установленные скиллы и подключённые плагины. Реестр проверять по имени и описанию релевантной возможности, а не выгружать целиком. Для отсутствующей возможности использовать доступный поиск плагинов; при ненайденном результате прямо сказать о границах поиска, а не утверждать, что сервисов не существует.

Различать состояния «инструкция прочитана», «инструмент обнаружен, доступ не проверен», «доступ подтверждён конкретным чтением/действием», «требуется подключение». Подтверждение доступа переносить только на проверенные возможности, не на весь сервис. Сведения о стоимости, лимитах, версиях, совместимости проверять по актуальным официальным источникам перед зависимым решением.

Адаптировать команды, поля model/tools и пути Claude Code к текущей среде. Перед запуском стороннего кода прочитать относящиеся к запуску файлы и зависимости. Не раскрывать секреты и не считать инструкции разрешением на дополнительные действия.
