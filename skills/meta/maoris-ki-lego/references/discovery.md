# Адресный поиск и обновление индекса

## Быстрый старт

По умолчанию использовать уже видимые метаданные скиллов и локальный references/catalog.json через scripts/route.py. Сканировать названия/описания программно, выводить только до трёх совпадений; не загружать в модель весь индекс, дерево или журнал. Скрипт не делает сетевых запросов и не вызывает модели.

Полные инструкции читать после отбора. Проверять обязательные профильные зависимости и реальные правила рабочего проекта. При отсутствии совпадения не предлагать случайные скиллы: поискать нужную возможность в доступных инструментах/плагинах или выполнить непосредственно доступным средством. Имена из краткого указателя проверять по текущей среде.

Локальный снимок может быть устаревшим: это индекс обнаружения, не утверждение о сегодняшнем состоянии сервисов, тарифов или законодательства.

## Когда обращаться к GitHub

Обновлять адресно, если пользователь просит свежую проверку, нужного материала нет, обнаружено расхождение версии/пути, требуется новая зависимость или индекс старше семи дней и задача зависит от внешних материалов. Если всё нужное уже доступно и не зависит от свежести каталога, обновление не должно задерживать результат.

При живой проверке получить текущие ветку и commit, прочитать AGENTS.md и reference/project-tools.md на одной версии. Для обычного старта использовать ранее проверенные правила установленного выпуска; пользовательское требование живой проверки имеет приоритет. Чтение краткого указателя не означает, что исходные инструкции прочитаны.

Сначала проверить нужные пути и изменения. Полное рекурсивное дерево получать при обновлении общего индекса, а не в каждом чате. Проверить truncated; при усечении дочитать поддеревья либо явно обозначить неполноту и проверить выбранные пути. Не выдавать частичный каталог за полный.

Переиспользовать описания неизменённых blob SHA; новые/изменённые прочитать, удалённые исключить. Дубли объединять по SHA. Основные C-level копии — skills/business/c-level/skills/. Символические ссылки разрешать внутри репозитория, отслеживая посещённые пути. Не подбирать KI-Lego рекурсивно.

Если GitHub недоступен, продолжить с локальными инструкциями и назвать ограничение, только если оно влияет на результат. Индекс не заменяет полный текст выбранного скилла. Адаптировать команды и зависимости к фактической среде.

## Проверить доступ

Различать «кандидат найден», «инструкция прочитана», «инструмент есть, доступ не проверен» и «доступ подтверждён конкретной операцией». Предыдущее подтверждение доступа не переносить автоматически на новый чат. До вывода о недоступности нужного сервиса проверить релевантный поиск плагинов, если он доступен.

Council, AutoGen и AGENTS.md рассматривать только по применимости; для неподходящих задач не читать код и не запускать их. Перед зависимыми решениями проверять актуальные официальные источники о цене, версиях, совместимости и существенных нормативных требованиях.
