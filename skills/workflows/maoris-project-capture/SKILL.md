# Память проекта

Сохранить мысли и принятые решения так, чтобы следующий рабочий чат мог продолжить с актуального места. Писать коротко, естественным языком; не требовать заполнения формы от пользователя.

## Порядок работы

1. Определить конкретный проект и направление: NS, MDL или иной. Найти существующий документ состояния и папку по доступным подключённым источникам. Если источник назван — прочитать его текущую версию; историческую память использовать как ориентир поиска. Не объединять клиентские данные NS и продуктовые документы MDL.
2. Работать с доступной перепиской, предоставленными файлами и найденными источниками. При просьбе собрать все прошлые чаты обозначить реально доступное покрытие; не выдавать выборку за полный архив. Сначала собрать доступное; запросить только существенные отсутствующие материалы.
3. Разделить: идеи пользователя; явно принятые решения; проверенные факты с источником; предположения ассистента; нерешённые вопросы. Более позднее «может быть» не отменяет прежнее решение. Не придумывать согласие, владельца, срок или выполненную задачу.
4. Подготовить компактную запись по [record.md](references/record.md). Включить существенные отвергнутые варианты с причиной, чтобы не предлагать их заново без изменившихся оснований. При конфликте источников назвать расхождение; безопасную часть сохранить, зависимое решение уточнить.
5. Если поручено сохранить — сохранить в существующем проекте по правилам среды. В рабочем репозитории обновить существующий docs/PROJECT_STATE.md или аналог; для идей использовать уже выбранную папку документов. Если места ещё нет, выбрать подходящее постоянное место из контекста и доступных средств. Не складывать частные проекты в публичный KI-Lego и не создавать несколько конкурирующих архивов.
6. Обновлять существующий объект с сохранением его идентичности и истории; перед записью сверить актуальную версию и сохранить чужие изменения. После успеха дать ссылку и кратко назвать добавленное. Текст в ответе или локальный временный файл не называть долговременным сохранением.
7. При возобновлении сначала прочитать краткое состояние и указанные необходимые источники, затем сверить действующие файлы и доступ. Загружать подробные исходники только по текущей необходимости.

## Границы

Это ведение проектной записи, не автоматический сбор всех чатов и не общий журнал опыта KI-Lego. Профильные тексты, таблицы и документы создавать существующими инструментами. Никаких новых сервисов, рассылок, сроков или назначений людям из одного поручения сохранить мысли.

## Основание

Адаптирован принцип отделения обсуждения от решений из decision-logger (Alireza Rezvani, MIT) в KI-Lego. Облегчённый порядок выше самодостаточен; запуск boardroom и загрузка сырых транскриптов не требуются.
