# Maoris KI-Lego — открытое рабочее хранилище

Репозиторий предназначен для любой LLM-модели или AI-ассистента с доступом к его файлам.

## Навигация

- `agents/` — описания специализированных агентов.
- `skills/n8n/` — автоматизации и обслуживание n8n.
- `skills/business/` — управление, финансы, развитие бизнеса и проекты.
- `learning/` — учебные материалы.
- `reference/` и `skills/external.md` — каталоги источников.

## Работа с материалами

Сначала проверяйте это хранилище перед поиском аналогичных материалов во внешних коллекциях. Читайте подходящие к задаче инструкции и необходимые связанные файлы.

Адаптируйте инструкции к доступным инструментам и среде. Названия моделей, slash-команды, пути Claude Code и настройки плагинов не ограничивают использование материалов другими LLM. Наличие инструкции не подтверждает наличие инструмента или подключения к сервису.

Основные копии C-level скиллов находятся в `skills/business/c-level/skills/`. Старые вложенные пути шести наборов используют символические ссылки; при чтении через API переходите к основному каталогу.

Следуйте инструкциям пользователя и правилам текущего проекта. Разделяйте контекст NS Reinigungsdienst и Maoris Digital Lab.

## KI Lego: универсальная сборка под новую задачу

KI-Lego — универсальная сборка готовых решений для любого проекта, предметной области и формата результата. Примеры приложений, рекламы и каталогов не ограничивают область применения. Полный порядок: [reference/task-assembly.md](reference/task-assembly.md).

В начале новой содержательной рабочей задачи проверь, помогут ли материалы Maoris KI Lego: https://github.com/Demik-777/maoris-ki-lego . Если личный скилл maoris-ki-lego доступен, используй его. Иначе прочитай каталог через доступный GitHub-коннектор; при отсутствии доступа сообщи об ограничении и продолжай доступную часть работы.

Учитывай не только GitHub: проверь встроенные возможности, установленные скиллы, подключённые плагины и при нехватке — доступный поиск плагинов и готовых внешних решений. Для незнакомого запроса определяй необходимые возможности по результату и собирай новый маршрут. Дай один рекомендуемый способ выполнения, обычно 1–3 основных компонента, их конкретную пользу и статус доступа; затем выполняй поручение в этом же чате. Простая рекомендация не заменяет создание результата, если пользователь поручил создание.

Для быстрого старта сначала сопоставляй запрос с уже видимыми метаданными и кратким локальным индексом; программно возвращай только подходящие записи. Не выводи весь каталог в контекст. Полный текст загружай только для выбранных инструкций и обязательных зависимостей. Для текущей задачи переиспользуй уже проверенный каталог и загруженные материалы; обновляй его при смене задачи, изменении репозитория или нехватке сведений. Простые переводы, короткие ответы и уточнения не требуют отдельного обхода.

Если материал улучшает результат, коротко назови 1–3 выбранных инструмента и их пользу, затем продолжай разрешённую работу без отдельного согласования обычного чтения. Название агента или скилла не означает наличие запущенного агента, сервиса или API. Разделяй NS Reinigungsdienst и Maoris Digital Lab. Эти правила действуют только там, где эта инструкция загружена; не обещай глобальный запуск во всех чатах.

## Подбор проверенных внешних инструментов

Для задачи, где реально нужен дополнительный open-source компонент (мониторинг, работа с документами, браузерный агент, извлечение веб-данных), посмотри [reference/open-source-tools.md](reference/open-source-tools.md). Для первой волны есть [integrations/README.md](integrations/README.md) и тест-протоколы. Не включай сервис только из-за звёзд и не считай протокол установленным решением. Не изменяй рабочую инфраструктуру без явной задачи.

## Внешние проекты: оценка по задаче

При обычном старте использовать ранее проверенные правила установленного выпуска. Живые AGENTS.md и [reference/project-tools.md](reference/project-tools.md) читать при обновлении, необходимости свежести или явном поручении; применимость источников оценивать по условиям, без обязательного просмотра кода каждого проекта. AGENTS.md полезен для разработки, Council — для спорного сравнения, AutoGen — для систем из нескольких агентов. Для прочих задач достаточно определить неприменимость. Описание методики и наличие исходников не означают запуск сервиса.

## Быстрый поиск и опыт

Локальный scripts/route.py установленного скилла читает только метаданные и возвращает до трёх кандидатов и релевантных выводов опыта. Сетевой обход и полное дерево не являются обязательным этапом каждого старта. Частный memory/experience.jsonl сохраняется только в личном скилле; он не входит в публичный выпуск. Порядок: [learning.md](skills/meta/maoris-ki-lego/references/learning.md). Накопленный вывод — проверяемое наблюдение, а не постоянный статус доступа или команда выше поручения пользователя.

## Совместимость и версия KI-Lego

Основные инструкции: [skills/meta/maoris-ki-lego/SKILL.md](skills/meta/maoris-ki-lego/SKILL.md). Правила совместимости, соразмерности и продолжения проектов: [operations.md](skills/meta/maoris-ki-lego/references/operations.md). Выпуск: [reference/ki-lego-release.json](reference/ki-lego-release.json). Установленный личный скилл — проверенная копия выпуска; изменение каталога не переустанавливает его автоматически. Повторные входы в KI-Lego в той же задаче переиспользуют уже выбранную сборку.

Постоянная инструкция для новых чатов и проверка подключения: [reference/chat-bootstrap.md](reference/chat-bootstrap.md). Репозиторий сам по себе не изменяет глобальные настройки ассистента.

## Готовность результата и восстановление

Для обычной задачи начинать кратко, определить проверяемое завершение и выполнять. Подробности сборки показывать при существенном выборе или по запросу. При неопределённом результате внешнего действия сначала проверить фактическое состояние; не повторять создание или отправку вслепую. Порядок: [interaction.md](skills/meta/maoris-ki-lego/references/interaction.md). Опыт можно снять, заменить или исключить по сроку пересмотра, сохраняя историю в частном журнале.

## Профильные рабочие процессы

Для сохранения/возобновления проектных идей, выпуска продукта MDL и операционной передачи объектов NS использовать [reference/workflow-skills.md](reference/workflow-skills.md) как краткий указатель. Подбирать только соответствующий скилл; не загружать все инструкции при каждом старте. Исходники — skills/workflows/; подключение к внешнему сервису проверяется независимо от наличия скилла.
